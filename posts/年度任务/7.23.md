# Java / Kotlin 编程基础核心解析

## 模块一：方法声明解析 (`public static void tell()`)

在 Java / Kotlin 的方法声明中，各个关键字扮演着完全不同的角色。它们依次回答了四个核心问题：**谁能用？怎么用？返回什么？叫什么？**

$$\underbrace{\text{public}}_{\text{1. 权限}} \quad \underbrace{\text{static}}_{\text{2. 归属}} \quad \underbrace{\text{void}}_{\text{3. 产出}} \quad \underbrace{\text{tell()}}_{\text{4. 名称与参数}}$$

### 1. 核心要素对比

|**关键字/要素**|**解决的问题**|**概念与作用**|**缺省/不写会怎样？**|
|---|---|---|---|
|**`public`**|**谁能访问？**|**访问控制修饰符**。表示该方法是“公开的”，任何包或类均可直接调用。|变为 **包级私有（Package-Private）**，仅限同包内的类调用。|
|**`static`**|**怎么调用？**|**静态修饰符**。表示该方法属于**类本身**，无需实例化即可直接通过 `类名.方法()` 调用。|变为 **实例方法**，必须先通过 `new` 实例化对象后才能调用。|
|**`void`**|**返回什么？**|**返回值类型**。表示该方法执行完后**不返回任何数据**。|**语法错误！** 普通方法必须显式指定返回值类型（如 `int`, `String`）或使用 `void`。|
|**`tell()`**|**叫什么？**|**方法名与参数列表**。`tell` 为标识符，`()` 内定义传入参数。|**语法错误！** 方法必须包含名称与参数括号。|

### 2. 深入理解 `static`（静态 vs 实例）

Java

```
// 1. 静态方法（属于类本身）
public class Tools {
    public static void tell() {
        System.out.println("静态方法：直接通过类名调用");
    }
}
// 调用方式：Tools.tell();

// 2. 实例方法（属于对象）
public class Person {
    public void tell() {
        System.out.println("实例方法：必须先 new 出对象");
    }
}
// 调用方式：Person p = new Person(); p.tell();
```

### 3. 访问修饰符细节（省略 `public`）

如果不写 `public`，方法将获得 **默认访问权限（包级私有）**：

Plaintext

```
src/
 ├── com.example.a/
 │    ├── AClass.java  --> 定义了 static void tell()
 │    └── BClass.java  --> 同包：✅ AClass.tell() 可正常调用
 └── com.example.b/
      └── CClass.java  --> 跨包：❌ 编译报错，无法访问
```

> **例外情况：** Java 程序的标准入口 `public static void main(String[] args)` 中，`public` **不可省略**，否则 JVM 将无法读取入口。
> 
> **Kotlin 差异：** Kotlin 的默认访问权限即为 `public`，因此 `public` 关键字通常省略不写。

### 4. 返回值类型细节（`void` vs 非 `void`）

- **`void`**：仅执行逻辑，不向调用者交付数据，无需（或仅用 `return;`）结束方法。
    
- **具体类型（如 `String`, `int`）**：必须包含 `return` 关键字，且返回值的类型必须与声明严格匹配。
    
- **语法例外（构造方法）：** 类的构造函数（`public Person()`）不需要写任何返回值类型，也不需要写 `void`。
    

## 模块二：变量分类与作用域（类内 vs 类外/局部）

在面向对象语言中，不同位置定义的变量在结构（内存/生命周期）**与**功能（作用域/用途）上有着本质区别。

### 1. Java 视角：类成员变量 vs 方法局部变量

Java

```
public class Demo {
    // 成员变量（属性）
    int memberVar = 10; 
    static int staticVar = 20;

    public void test() {
        // 局部变量
        int localVar = 30; 
    }
}
```

- **结构区别：**
    
    - **内存存储：** 成员变量位于 **堆内存（Heap）** 或 **元空间（方法区）**；局部变量位于 **栈内存（Stack）**。
        
    - **生命周期：** 成员变量随对象的创建而分配、随垃圾回收（GC）而销毁；局部变量随方法压栈创建，**方法执行完毕出栈即销毁**。
        
    - **默认初始化：** 成员变量拥有默认值（如 `0`, `null`, `false`）；局部变量 **无默认值，必须显式赋值后方可使用**。
        
- **功能区别：**
    
    - **成员变量：** 用于持久化记录 **对象的状态与特征**，数据可在类内多方法间共享。
        
    - **局部变量：** 用于 **暂存临时计算过程的中间数据**，作用域仅限于定义它的 `{}` 代码块内。
        

### 2. Kotlin 视角：类属性 vs 顶层变量（Top-Level）

Kotlin

```
// 顶层变量（文件最外层）
val globalConfig = "App_Config"

class User {
    // 类属性
    var name: String = "John"
}
```

- **编译底层：** 类属性会自动生成私有字段与 Getter/Setter 方法；顶层变量在编译为字节码后，底层会被包装为 Java 静态变量（`public static`）。
    
- **功能定位：** 类属性遵循面向对象的封装原则，各实例独立存在；顶层变量在包范围内共享，常用于定义全局常量或工具函数。
    

### 3. 变量特性总结对比

|**比较维度**|**类内变量 / 属性（Member / Property）**|**局部变量（Local Variable）**|**顶层变量（Top-level，Kotlin）**|
|---|---|---|---|
|**内存位置**|堆内存（Heap）/ 元空间|栈内存（Stack）|静态方法区 / 元空间|
|**生命周期**|随对象生存，由 GC 回收|方法出栈即销毁|随程序启动生成，随进程终止销毁|
|**默认初始值**|**有**（如 `0` / `null`）|**无**（必须手动初始化）|**有**（须在声明时显式赋值）|
|**作用域**|整个类内部（受访问修饰符约束）|仅限声明它的 `{}` 内部|整个包或全项目（导入后）|
|**核心功能**|记录对象的**持久状态**|辅助**临时运算**|维护**全局共享配置/常量**|

## 模块三：Java 中的“全局变量”机制

### 1. Java 是否存在类外全局变量？

**结论：绝对没有。**

Java 是一门纯粹的面向对象语言，其语法规则严格限制：**所有变量与方法必须定义在类（`class`）或接口（`interface`）内部**。在 `.java` 文件最外层声明变量会导致编译报错。

Java

```
// File: Demo.java
package com.example;

int globalX = 100; // ❌ 编译报错：Syntax error, insert "ClassBody" to complete BlockStatements

public class Demo {
    // 变量必须定义在类体内
}
```

### 2. 标准实现：通过静态变量（`static`）模拟全局变量

为了在 Java 中实现全局可访问的状态或配置，标准做法是使用 **`public static`**（或加上 `final` 作为常量）：

Java

```
// 全局配置/状态类
public class Global {
    // 全局常量
    public static final String APP_NAME = "MyDesktopApp";
    
    // 全局可读写变量
    public static int currentOnlineUsers = 0;
}

// 任意位置直接调用：
public class Test {
    public void run() {
        System.out.println(Global.APP_NAME); // 直接通过 类名.变量名 引用
        Global.currentOnlineUsers++;
    }
}
```

### 3. 多语言对比

- **C / C++ / Python：** 支持原生全局变量，可以直接定义在文件最外层。
    
- **Kotlin：** 支持顶层变量（Top-level Variable），但编译为 Java 字节码后本质仍会被转换为静态属性。
    
- **Java：** 坚决不允许任何变量脱离类结构而独立存在。
